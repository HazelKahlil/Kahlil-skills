# Kahlil AI-Look 发布闸门

## 目的

Kahlil Card 的最终交付不只检查图片版式，也要检查面向读者的文字。所有卡面文案和默认的小红书发布文案，在交付前都必须经过 `kahlil-ai-look` 的**去痕模式**，由 Agent 自动检查并改写一次。

这不是让文字变得更漂亮，也不是事实核查。去痕只处理 AI 写作指纹，保留事实、判断、专名、数据、卡片结构和账号语气。

## 固定顺序

```text
提取面向读者的文字
  → 卡面文字先过 kahlil-ai-look 去痕
  → 把去痕后的文字写回 index.html
  → render PNG
  → 可选版式 validator
  → 写发布文案初稿
  → 发布文案再过 kahlil-ai-look 去痕
  → 保存最终文案
  → 交付
```

这是文字闸门的默认自动流程。除非用户明确说“只做检测”“只保留原稿”或“跳过 AI-Look”，否则不询问是否执行。

`validate-social-deck.mjs` 仍然是视觉版式校验，按现有策略由用户要求时运行；它和 AI-Look 是两条不同的 QA 线。

## A. 卡面文字闸门

在第一次 `node render.mjs` 之前，提取 `POSTERS_HERE` 中所有面向读者的文字，包含标题、导语、正文、数据说明、引语和结尾判断。

1. 读取并调用 `kahlil-ai-look` Skill。
2. 明确使用**去痕模式**，不要停在检测报告，也不要等待用户确认。
3. 保留事实、判断、经历、行动、数字、产品名和人名；不新增未经证实的信息。
4. 只把修改后的卡面文案写回任务目录的 `index.html`。
5. 如果卡面文字发生变化，必须重新渲染 PNG，再继续版式 QA。

以下内容不进入 AI-Look：`Hazelkahlil`、`Issue`、`Vol.`、`Recipe` 等固定品牌 chrome，以及仅供制作流程使用的 HTML 注释和文件名。

## B. 发布文案闸门

成图和版式 QA 完成后，先生成一份发布文案初稿，再做最后一次去痕。默认小红书文案仍须遵守 `references/xhs-caption.md` 的标题、正文、标签和字数规则。

1. 初稿保存为本次时间戳目录的 `发布文案-初稿.txt`。
2. 自动调用 `kahlil-ai-look` 的**去痕模式**，不询问用户是否需要检查。
3. 将去痕后的完整文案保存为 `发布文案.txt`。
4. 将改动摘要保存为 `AI-Look-检查报告.md`，至少写明检查完成、改动范围和事实/专名保留情况。
5. 对话中只贴 `发布文案.txt` 的最终可复制版本，不贴初稿，也不把检查报告混进正文。
6. 除非用户另有要求，不交付 `发布文案-初稿.txt` 的内容。

## 失败处理

- `kahlil-ai-look` 不可用、调用失败或只返回诊断而没有改写结果时，不得把文案标记为“已通过 AI-Look”。保留初稿，说明闸门未完成，暂停最终文案交付。
- AI-Look 修改了卡面文字时，旧 PNG 不再是最终产物，必须重渲并重新做版式检查。
- AI-Look 不负责核验会议、价格、数据、引用或图片来源；这些仍按原有事实和素材 QA 流程处理。
- 图片本身的构图、字体、溢出、裁切和品牌一致性仍由 `validate-social-deck.mjs` 与人工视觉检查负责。

## 最终交付文件

```text
输出/<H时MM分>/
├── 卡片-01.png …
├── 发布文案-初稿.txt
├── 发布文案.txt

```

最终交付以 `发布文案.txt` 为准。`发布文案-去痕后.txt` 是旧流程的历史命名，新任务不再使用。
