# 小红书发布文案（Caption）

卡组成图后，**默认同交付一份可直接粘贴的发布文案**。
卡片吃不下全文时，正文只取钩子 + 一段精华，结尾导图一句即可。

## 交付形态（硬）

成图 QA 通过后，先生成初稿并自动经过 `kahlil-ai-look` 去痕；闸门完成后再在对话里给出最终文案。用户要的是**一下复制**，不要拆成「标题块 / 正文块 / 标签块」三段讲解。

### 对话与落盘的同一格式

```text
{标题}

{正文}
{标签行}
```

规则：

1. **第 1 行**：标题（单独一行）。
2. **空一行**。
3. **正文**：段落之间正常空行；**最后一句**导图（默认：`完整版都在上面的图片里。`）。
4. **正文最后一句的下一行起直接接标签**——**中间不再空一行、不加「标签：」小标题、不另起说明段**。
5. 标签用**空格**分隔，**默认同一行写完** 3–5 个；**禁止**换行拆标签，**禁止** `#AI#GPT` 无空格黏连。
6. 对话里**不要**再包一层 `**标题**` / `**正文**` / `**标签**` 或「字数验收」——除非用户追问。
7. 需要给路径时：路径放在可复制正文**之前或之后**，用一句话带过，**不要插进可复制段中间**。

### 落盘

```text
platforms/Kahlil-cards/<YYYY年M月>/<D日>/<专题中文名>/输出/<H时MM分>/
├── 发布文案-初稿.txt
├── 发布文案.txt
└── AI-Look-检查报告.md
```

`发布文案.txt` 的文件内容 = 上面整段（标题 + 空行 + 正文接标签），编码 UTF-8。初稿只用于闸门前留档，最终交付以 `发布文案.txt` 为准。

## 硬规则

| 项 | 规则 |
|----|------|
| 标题 | ≤ **20** 字（汉字/字母/数字均计 1；不含前后空白） |
| 标签 | **3–5** 个，每个以 `#` 开头 |
| 标签排布 | **同一行**、空格分隔；**不要**换行拆开，**不要**无空格黏连 |
| 计数字段 | **正文原始文本 + 标签**（含换行符）；**标题不计入** |
| 合计字数 | 正文 + 标签必须在 **800–1000**（含端点） |
| 平台 | 默认小红书图文笔记 |

字数验收：对「正文 + 紧随其后的标签」整段 `len(text)`（Python），**换行算 1**。交付时不必展示计数，自己卡进区间即可。

## 正文怎么写

1. **不求复述全文**。原文长时，只保留：钩子（是什么 / 为谁）+ **一个**可感知片段（案例、对比或一步上手）。
2. **结尾导图**：默认一句 `完整版都在上面的图片里。` 足够；用户另指定措辞时从其指定。不必再叠「右滑 / 按页看」等多句 CTA。
3. 口语、可扫读；少用内部制作词（S01、ledger、recipe、Issue 等）。
4. 需要凑字数时：**加深钩子与案例**，不要堆同义反复，不要为凑字把标签拉长串。

## 标题怎么写

- 优先：人群 + 结果 / 反差（如「零基础」「文科生」「一人」「不用写代码」）。
- 可含专有词：`Vibe Coding`、`AI`、`GPT` 等，仍计入 20 字上限。
- 忌空泛大词堆叠；忌超过 20 字硬塞副标题。

## 标签怎么选

### 原则

- **流量池要大** + **和本篇人群/主题准**。
- 优先持续搜索/推荐池，不堆一次性长尾冷词。
- **3–5 个封顶**；宁少勿滥。

### 选题池参考（AI / 上手向）

写 AI 工具、氛围编程、零代码上手时，优先从下面大池里挑 **3–5** 个（按篇微调，不必每次用满）：

| 标签 | 池子角色 |
|------|----------|
| `#AI` | 最大泛池 |
| `#GPT` / `#ChatGPT` | 工具认知池（二选一，勿重复堆） |
| `#小白` | 入门人群 |
| `#零基础` | 入门人群 |
| `#文科生` | 非技术人群（内容匹配时用） |
| `#skill` / `#AI技能` | 方法/技能向（内容匹配时用） |

可按篇替换/追加 1 个更准的中大词（如 `#编程` `#独立开发` `#一人公司`），但总数仍 ≤5，且不要挤掉所有大池。

### 反例

- `#VibeCoding氛围编程教程合集2026文科生转型`（过长、过窄、难进池）
- 一次贴 8–12 个标签
- 标签黏成一行无分隔：`#AI#GPT#小白#零基础`
- 标签拆成多行（应单行空格分隔）
- 正文结束后空一大段再写标签，或加 `【标签】` 标题（破坏一键复制）

## 与卡组的关系

| 载体 | 承担 |
|------|------|
| 图片卡组 | 结构、步骤、对比、清单（视觉大纲） |
| 发布文案 | 钩子 + 一小段可读原文气质 + 一句导图 + 标签紧接 |

卡面已经讲过的长流程，**不要**在正文再抄一遍。

## 工作流位置

`SKILL.md` 工作流：提取卡面文字 → **kahlil-ai-look 去痕** → 写回 `index.html` → 渲染 → QA → 写 `发布文案-初稿.txt` → **kahlil-ai-look 去痕** → 复核格式与字数 → 写入 `输出/<时间戳>/发布文案.txt` → 在对话贴出可复制全文 → 交付路径。

AI-Look 闸门的完整规则见 [`ai-look-gate.md`](./ai-look-gate.md)。它只处理 AI 写作指纹，不替代事实核查、图片来源核验或版式 QA。
