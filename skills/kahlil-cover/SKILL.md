# Kahlil Cover

## 核心原则

Cover 有且只有两种正式模式：`IP 角色版` 与 `内容视觉版`。模式决定视觉系统，文章决定画面真正表达的判断和动作。

用户已指定模式时直接执行；未指定时先询问“IP 角色版还是内容视觉版？”，不得擅自选择。

参考图优先于通用风格描述。用户给出满意成图或参考图时，先提取其构图、标题层级、配色、画面密度和留白，再在所选模式内复现这些锚点。参考图只校准视觉，不得把另一篇文章的主体、场景或隐喻带入当前封面。

## 输入

- 文章、口播稿、摘要或清晰的选题说明。
- 用户给出的标题；未提供时才建议标题。
- 模式：`IP 角色版` 或 `内容视觉版`。
- 可选：画幅、平台、参考图、参考风格、人物素材。
- 默认画幅为 `3:4` 竖版；只有用户明确提出时才改用其他比例。
- 右下角只放很小的 `Kahlil` 署名，低调、低存在感，不做徽章，不加底色框。
- 不自动添加 `AICONVERSATION`、Footer、栏目名或其他文字。

## 内容提取

生成提示词前，先在内部形成六项 brief：

| 字段 | 要回答的问题 |
| --- | --- |
| 核心判断 | 观众只记住一句什么？ |
| 目标读者 | 这篇内容在和谁说话？ |
| 主要张力 | 什么变化、障碍或反差推动画面？ |
| 视觉动作 | 谁正在做什么具体动作？ |
| 主视觉 | 哪个人、物件或场景承担主题？ |
| 情绪 | 画面要让人感到清楚、好奇、紧张、克制还是温暖？ |

画面必须表达文章的核心判断。把标题遮住后，如果这张图仍能无差别地用于另一篇文章，就重新提取。

## 模式路由

| 用户输入 | 执行方式 |
| --- | --- |
| 明确选择 IP 角色版 | 使用 Hazel 观察者固定人物与手绘视觉语言 |
| 明确选择内容视觉版 | 根据文章重新决定人物、物件、环境、媒介与风格 |
| 没有选择模式 | 只询问模式，收到回答后再写提示词 |
| 提供满意成图或参考图 | 在已选模式内启用参考图覆盖层 |

## IP 角色版

**REQUIRED SUB-SKILL:** 使用 `kahlil-artwork` 的角色契约、Style DNA、动作规则和负面约束。

生成前要求用户把以下两张 canonical reference images 上传给 ChatGPT，顺序不变：

1. `kahlil-artwork/assets/canonical/01-action-library.png`
2. `kahlil-artwork/assets/canonical/02-workflow-language.png`

如果当前环境同时安装了本仓库的 `kahlil-artwork`，使用其对应的两张 canonical 图；如果没有安装，先提示用户提供这两张图或明确改用内容视觉版，不要编造角色一致性。

只把这两张图作为人物生成根参考。已生成的封面可用于人工验收和构图校准，但不得递归作为下一轮人物参考。

### 固定视觉合同

- 标题优先：标题占上方约 `40%–45%`，人物和文章动作位于下半区，手机缩略图仍能直接读懂。
- 长标题按语义拆成 `3–4` 个层级；只选一个关键短语作为最大字号，可使用“焦橙色关键词 + 细橙下划线”或“黑色关键词 + 细橙下划线”。
- 所有中文标题行统一使用同一套粗黑体/黑体字形与字重；上方说明句也不得使用宋体或其他衬线字体。
- 英文关键短语固定使用超粗无衬线，字号为全画面最大，可接近整行宽度。
- 底部中文结论句继续使用同一套粗黑体/黑体字形；通过字号、行距和位置形成层级，不靠切换宋体与黑体。
- 没有英文时，选一个中文核心短语承担“最大字号”层级；整组中文仍保持同一套黑体字形。
- 默认纯白背景，不设置房间、办公室、书桌、窗户或写实环境。
- 人物身份、黑帽、圆眼镜、深暖棕外套、白色脸手和炭灰手绘线必须与 `kahlil-artwork` 一致。
- 焦橙色只承担一个重点词、路径、动作或结果信号，不把整张图染成橙色。
- 人物必须亲手完成文章隐喻中的关键动作。固定的是人物，不是纸盒、卡片或某个历史动作；每篇文章都重新设计动作和道具。
- 删除人物后如果文章含义仍完整，说明人物只是装饰，必须重写视觉动作。

### IP 角色版交付结构

1. 一句话说明画面判断与人物动作。
2. 给出两张 canonical reference images 的可点击路径和上传顺序。
3. 输出一条可直接复制给 ChatGPT 的完整生图提示词。

提示词必须写明：只参考角色身份、动作语言、线条和配色，不照抄参考图构图，不拼贴参考图。

## 内容视觉版

内容决定风格与主体。每篇文章重新确定人物、动作、物件、环境、媒介、色彩、光线与情绪；不强制出现 Hazel 观察者。

不得复用另一篇文章的主视觉、场景或隐喻，只替换标题不算完成内容路由。把标题遮住后，如果图片可以无差别用于另一篇文章，就重新提取。

## 风格路由

内容决定风格与主体，品牌只固定少量版式规则。

| 内容类型 | 优先画面 |
| --- | --- |
| AI 入门 / 方法教程 | 普通人使用工具的具体动作、清楚的输入与输出、可检查的结果 |
| AI 观点 / 趋势判断 | 一个明确的选择、限制、代价或状态变化 |
| 产品 / 工具发布 | 产品解决的真实任务与使用场景，不画悬空设备广告 |
| 艺术 / 文化 | 与文章对象直接相关的材料、空间、观看或制作动作 |
| 个人经历 | 真实人物位置、生活物件和发生过的动作，不编造戏剧场景 |

内容视觉版默认使用内容驱动的编辑摄影或编辑插画。人物、静物、空间、色彩、光线都由当前文章决定。

莫兰迪历史风格仅在用户明确选择，或文章本身讨论莫兰迪时使用。旧瓶子、花瓶、画室木架和 `morandi-cover-final-optimized.txt` 都是单篇历史资产，不是通用母版。

## 品牌与排版

- `3:4` 竖版默认输出。
- 标题文字和词序必须保留，不翻译、不改写、不缩写；可按语义分行，标点可省略或调整。用户明确要求保留标点时才逐字保留。
- `IP 角色版` 使用标题优先的大层级排版；`内容视觉版` 根据画面把标题放在上半区或左上安全区，主体不能挤压标题。
- 右下角放很小的 `Kahlil`，不得做成高对比徽章、白框标签或第二视觉中心。
- 画面只保留标题和品牌；用户没有要求时不添加副标题、栏目名、Footer、Logo 或水印。

## 内容视觉版提示词结构

输出一条可直接复制的完整提示词，按以下顺序写：

```text
Create a finished [比例] vertical editorial cover for [内容类型].

Article-derived concept:
- Core judgment: [核心判断]
- Main subject: [主视觉]
- Physical action: [视觉动作]
- Scene and relationship: [具体场景、输入输出或前后变化]
- Mood, palette and lighting: [由文章决定的情绪、颜色和光线]

Composition: [标题安全区、主体位置、景别和留白]

Render the headline words without rewriting: "[标题]". Punctuation may be omitted for layout.
[字体、颜色、分行和可读性要求]

Place a very small, quiet "Kahlil" signature in the lower-right corner. It must not look like a badge.

Negative constraints: [针对当前选题的负面约束，以及无多余文字、无乱码、无水印]
```

负面约束必须针对当前内容。AI 主题默认排除发光大脑、机器人头像、代码雨、蓝紫霓虹、全息界面和廉价科技海报；只有文章确实需要时才允许其中某项。

## 交付前检查

- 主体、动作和物件是否来自当前文章，而非历史 Prompt？
- 遮住标题后，画面是否仍能表达当前文章？
- 是否误带莫兰迪瓶子、旧画室、其他文章人物或道具？
- 画面是否只有一个主要视觉动作？
- 模式是否由用户选择；未指定时是否先询问？
- 标题文字、默认 `3:4` 和右下角极小 `Kahlil` 是否正确？
- IP 角色版是否保持标题优先、纯白背景、人物下半区和 canonical 根参考？
- 是否写明内容相关的负面约束和“不得生成额外文字”？

任一项失败就重新写提示词，不交付只换标题的旧模板。

## 常见错误

| 错误 | 修正 |
| --- | --- |
| 每篇文章都套同一静物 | 重新提取主视觉和视觉动作 |
| 只根据标题配图 | 同时读取文章判断、读者和张力 |
| AI 文章自动画赛博蓝光 | 先画真实使用动作和可见结果 |
| IP 版每次复用同一个纸盒 | 保留人物身份，重新设计文章动作和隐喻 |
| 用户未选模式就直接生成 | 先询问 IP 角色版或内容视觉版 |
| 长标题随意缩写 | 保留文字与词序，通过分行、字号和可省略标点解决 |
| `Kahlil` 做成醒目徽章 | 缩到右下角，只承担安静署名作用 |
